# AGENTS.md: Rules for AI Agents

This repository is an evidence-graded knowledge base for GenAI careers. These rules apply to any AI agent that answers questions from it or changes it. Humans: see [CONTRIBUTING.md](CONTRIBUTING.md).

## 1. Orientation

| Layer | Where | What it is |
|---|---|---|
| Evidence | `research/sessions/` | 22 dated research reports (October 2026). **Immutable.** |
| Knowledge | `research/findings.md`, `data/findings.json` | 262 key findings distilled from the sessions, each with grade and line |
| Reference and guidance | `career/NN-stage/` | User-facing documents on the lifecycle spine; every document has YAML front matter |
| Data | `data/` | Machine-readable sources of truth and their schemas |
| Machinery | `scripts/` | Generators (`--update` / `--check`) and the validator |
| Meta | `README.md`, `ROADMAP.md`, `CHANGELOG.md`, `research/DECISIONS.md`, `research/ERRATA.md` | Status, plans, history, decisions, corrections |

**Indexes for agents:**
- [llms.txt](llms.txt): every document with a one-line summary.
- [data/manifest.json](data/manifest.json): every document's front matter and section headings.
- Both are generated by `scripts/build_manifest.py`.

## 2. Sources of truth

| Topic | Edit this | Then run | It regenerates |
|---|---|---|---|
| Role scores and rankings | `data/role_scores.json` | `python3 scripts/rank_roles.py --update` | The generated blocks in `career/02-roles/role-rankings.md` |
| A–Z title index | the list `E` in `scripts/build_index.py` | `python3 scripts/build_index.py --update` | The index block in `career/02-roles/role-catalog.md` |
| Skills, role skill tiers, credentials, resume variants | `data/skills_ontology.json` | `python3 scripts/build_skills.py --update`, then `build_resume_matrix.py --update` and `resume_layers.py --update` | The skills vocabulary, the inventories index, `career/03-skills-and-tech/inventories/*.md`, the resume skills matrix and the job-search strategy's computed blocks |
| Project archetypes | `data/project_archetypes.json` | `python3 scripts/resume_layers.py --update` | The job-search strategy's computed blocks |
| Research findings | `research/sessions/*.md` (new sessions only) | `python3 scripts/build_findings.py --update` | `data/findings.json`, `research/findings.md` |
| Document index | front matter of any document | `python3 scripts/build_manifest.py --update` | `llms.txt`, `data/manifest.json` |

**Never hand-edit** anything between `BEGIN GENERATED` and `END GENERATED` markers, or any file whose front matter has `generated_by` without "(generated blocks)".

## 3. Answering questions from this repository

1. **Prefer the most distilled layer that answers the question:** career documents first, then the findings registry, then the sessions for detail.
2. **Cite the path and keep the grade and the date** ("AI Engineer is ranked #1 for GenAI targets [career/02-roles/genai-target-roles.md]"; "posted base is $180–248K, as of October 2026 [B · T0-01]").
3. **Check freshness:**
   - Figures are as of their stated dates.
   - Tool and credential statuses must be re-verified by 2027-01-21.
   - Check [research/ERRATA.md](research/ERRATA.md) before quoting FAD, DECISIONS, T1-01 or T2-01.
4. **Respect the evidence class:**
   - [P] means practice-curated, not measured.
   - M is a model output.
   - Feeder-title shares are labelled "(feeder)" or "(adjacent)" and are not the role's own measurement.
5. **Say when the repository doesn't know.** Stage READMEs mark stages as "Evidence only" when no guide exists yet; answer from the linked findings and sessions, and say so.
6. **Tax, visa and legal material** is pointers, not advice; keep the disclaimer.

## 4. Changing this repository

- **Evidence:**
  - Never edit `research/sessions/`. Corrections go to `research/ERRATA.md`; new evidence goes into a new session (see [research/README.md](research/README.md)).
  - `research/DECISIONS.md` is append-only: add a new decision rather than rewriting an old one.
- **Placement:**
  - Put content in the stage folder where it is used, and add it to that folder's `README.md`.
  - Docs use kebab-case file names; scripts and data use snake_case.
- **Every new document** under `career/` needs front matter that passes `data/schemas/frontmatter.schema.json`: `id`, `title`, `content_type`, `stage`, `status`, `version`, `last_verified`, `summary`, plus optional `sources`, `roles`, `geos`, `tags` and `generated_by`.
- **Evidence standard (EGP-1.0):**
  - Grade every empirical claim and attribute claims graded C or below.
  - Give dates; prefer ranges with reasons over single numbers when sources conflict.
  - Use [P] rather than citing a line that doesn't support the claim.
  - Never invent numbers.
  - No relative-time words ("now", "currently", "recently", "latest"); write dates.
- **Links:** relative only; never `file://`.
- **After any change:** run the generators you affected, then `python3 scripts/validate_docs.py`. It must print `PROBLEMS: 0`. CI runs it on every push. Then add an entry to [CHANGELOG.md](CHANGELOG.md).
- **Scripts:**
  - standard library only;
  - run with `python3 -B` or `PYTHONDONTWRITEBYTECODE=1`, so that no `__pycache__` is left in `scripts/`;
  - no temporary files in the repository.
